# Traducciones (i18n)

Los textos del código están en **inglés** y se traducen con ficheros `.po`
(gettext), que son los que usan Pootle, Weblate y cualquier editor de
traducciones. La actividad los **lee directamente**: no hay nada que compilar
(`i18n.py`).

| Qué | Dónde |
|---|---|
| Actividad | `po/Archivos.pot` (plantilla) y `po/<idioma>.po` |
| Cada plugin | `plugins/<id>/po/<id>.pot` y `plugins/<id>/po/<idioma>.po` |

## En el código

```python
from i18n import tr, ntr, N_

tr('Open')                                    # texto simple
ntr('%d file', '%d files', n) % n             # plural (reglas de Plural-Forms)
tr('%(folders)s and %(size)s in %(files)s') % {...}   # varios valores: con nombre
N_('Copying')                                 # marcar para traducir más tarde
```

- Los valores variables van con `%(nombre)s` cuando haya más de uno, para que el
  traductor pueda reordenarlos (en inglés «3 folders and 12.4 MB in 5 files»).
- Si un texto no se pasa por `tr(...)` en el momento (un diccionario, un parámetro),
  márcalo con `N_()` y tradúcelo al usarlo: `tr(_ACTION_TEXT[kind])`.
- Un plugin usa `self.tr` / `self.ntr` (su propio catálogo). Los nombres de
  los plugins se marcan con `N_`.
- `tr('DECIMAL_SEPARATOR')` se traduce como `,` en español: `i18n.decimal('12.4 MB')`
  da «12,4 MB».

## Idioma

`ARCHIVOS_LANG` (por ejemplo `es` o `es_ES`) manda; si no, `LANGUAGE`, `LC_ALL`,
`LC_MESSAGES`, `LANG`. `es_ES.utf8` busca `es_ES.po` y después `es.po`. Sin fichero
para el idioma se ve el inglés. Sugar pasa el idioma del usuario en `LANG`.

## Flujo de trabajo (`tools/translate.py`)

No necesita las herramientas de gettext (en el XO hay Python 2; el PC de desarrollo no
tiene por qué tener nada):

```
python tools/translate.py update          # extrae los textos y los pasa a cada .po
                                          # (los nuevos quedan sin traducir)
python tools/translate.py update --new ca # empieza un idioma nuevo (actividad y plugins)
python tools/translate.py check           # 0 problemas o código de salida 1
```

`check` falla si hay textos sin traducir, dudosos (`fuzzy`), que sobran o que faltan,
o con marcas de formato distintas (`%s`, `%d`, `%(x)s`) entre el original y la
traducción. La prueba `tests/test_i18n.py` ejecuta esa misma comprobación, así que
**no se puede añadir un texto sin traducirlo** sin que fallen las pruebas.

## Añadir un idioma

1. `python tools/translate.py update --new ca` crea `po/ca.po` y el de cada plugin.
2. Traducir los `msgstr`. Ajustar en la cabecera `Plural-Forms` (por ejemplo, el
   checo: `nplurals=3; plural=(n==1 ? 0 : n>=2 && n<=4 ? 1 : 2);`) y traducir
   `DECIMAL_SEPARATOR` (`,` o `.`).
3. `python tools/translate.py check`.

## Límites

- Se leen los `.po`, no los `.mo` (`dist_xo` de Sugar los compila, pero la actividad
  funciona igual sin ellos).
- No se extraen `msgctxt` ni comentarios para traductores; las entradas obsoletas
  (`#~`) se ignoran y `update` las elimina.
- El código fuente debe ser compatible con Python 2 (es lo que hay en OLPC OS 13.2).
